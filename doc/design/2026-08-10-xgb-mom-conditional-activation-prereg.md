## 1 · Hypothesis

The xgb_mom_60d model's cross-sectional signal concentrates in
high-dispersion market states, and that state is identifiable AT DECISION
TIME from prices alone — making conditional weighting (an MoE gate)
implementable without the regime-label causality wall (orch#930/#931: the
system's regime field is a close-of-run audit value and is NOT admissible
as an activation input; this design never touches it).

## 2b · TWO-STAGE STRUCTURE (review r2 — the post-selection BLOCKER is
accepted in full)

The hypothesis, variable, and threshold were formed AFTER inspecting the
same eight v2 folds — re-slicing those predictions cannot be confirmatory.
This proposal is therefore two stages with hard separation:

**Stage E (exploratory, the seen folds)**: the §2/§3 analysis runs on the
v2 OOS predictions but carries NO verdict authority — its output is
labeled hypothesis-refinement diagnostics, and no PASS/KILL is recorded
from it. Its committed artifacts are marked `stage: "E-exploratory"`.

**Stage C (confirmatory, unseen data — rule stated here, frozen by the
§5 harness PR before anyone looks)**: the SAME rule (ROC20-dispersion vs
its 252d median, threshold and definition immutable from this document
onward) is evaluated on the corpus EXTENSION window (entry dates from
2026-05-08 onward — data outside every v2 training set, outside the fold
windows that generated the hypothesis, and requiring the orch#939 corpus
extension). The §3 gates and §2 bootstrap apply in their Stage-C forms.
VERDICT TIMING IS DETERMINISTIC, NOT DISCRETIONARY: the confirmatory
verdict is recorded on the first date the frozen sample guards (n(A=1) ≥
100 and n(A=0) ≥ 100 entry days with REALIZED fwd_60d labels in the
extension window, plus the §3 gate-3 coverage guard) are met — by
calendar arithmetic roughly November 2026; earlier looks at the extension
outcomes are prohibited and the harness refuses to emit gate arithmetic
before the guards are met (fail-closed). An interim sign-only reading on
the ~3 realized-label extension days available today is explicitly NOT
provided: below the guards, no number is published.

The honest sentence for the operator, in the doc where it belongs:
confirmatory evidence about "when does this model work" cannot be
conjured from the data that suggested the question — Stage C's clock is
the price of a real answer.

## 3 · Gates (all required for a Stage-C PASS; Stage E records no verdict)

1. real-signal IC on A=1 days > 0 (bootstrap 95% CI excludes 0);
2. the A=1 − A=0 contrast > 0 (bootstrap 95% CI excludes 0);
3. mechanism-not-calendar, Stage-C form (review r3 — the 5-of-8
   fold-window coverage check was NOT Stage-C-evaluable: the extension
   window contains no v2 fold, so a Stage-C run could neither satisfy
   nor compute it): at the verdict date, A=1 entry days and A=0 entry
   days must EACH span ≥3 distinct calendar months of the extension
   window; unmet ⇒ no verdict, fail-closed — the deterministic clock of
   §2b extends to the first date every guard holds (an activation that
   is one contiguous calendar block is a calendar reading, not a
   mechanism reading). The historical 5-of-8 fold-window coverage check
   is demoted to a Stage-E DIAGNOSTIC: computed and reported from the
   seen folds, no verdict authority;
4. within-A placebo: the same contrast computed on shuffle ICs must NOT
   exclude 0 on the positive side.

PASS earns a conditional-weight rule PROPOSAL for the L2 allocation layer
(the mom expert's weight scaled by A(t)) — design only, behind the
serving gates (#931/#937) and its own review. KILL is a completed
outcome: the recent concentration is calendar, not identifiable
condition. Either way model#214's KILL for a STANDING arm stands.

## 4 · What this does not test

Sector conditioning (L2-S successor line); any regime-label input
(inadmissible per #930); book-level economics (IC-level only; the #927
cost lessons precede any deployment claim); no threshold or feature
search — the dispersion definition and threshold are single frozen
choices, and any variant is a new dated prereg.

## 5 · The freeze surface (review r3) — what the harness PR must commit before any run

The v2 result artifacts are per-fold AGGREGATES (model#214: "raw per-fold
output, aggregate-only") and carry no daily predictions — so both stages
require prediction generation, and a harness written after merge would
hold material degrees of freedom. This proposal therefore binds the
follow-up harness PR to commit, BEFORE any execution (the model#213
pattern: harness + verifier + controls land first):

1. **Extension scoring plan** — proposed frozen choice: the fold-8
   configuration (train 2016-01-01..2025-12-31 — every training date
   precedes every extension entry date ≥ 2026-05-08 — with the v2
   frozen 70-column feature list, params, and seeds, retrained
   deterministically from the sha-pinned corpus) scores EVERY extension
   entry date; NO refit inside the extension window; the v2 harness's
   per-row purge duty applies verbatim with the extension start as the
   boundary (every training row's realized 60d label endpoint strictly
   before 2026-05-08, purge counts persisted).
2. **Prediction artifact schema + hashes** — per-day rows (date, symbol,
   score), corpus sha256, feature-list sha256, model-config sha256, a
   `stage` field (`E-exploratory` / `C-confirmatory`), and the artifact's
   own sha256 recorded in the result JSON.
3. **Timestamp alignment, universe, missing-data rules** — A(t) from the
   ROC20 column at t−1 across the corpus universe present at t−1; rows
   with missing ROC20 excluded from the dispersion std with the
   exclusion count persisted per date; per-day IC computed on the
   intersection of scored symbols and realized fwd_60d labels, with the
   per-date counts persisted.
4. **Rolling-median warm-up** — the trailing 252-trading-day median at
   t−1 requires 252 prior corpus sessions of dispersion history; earlier
   dates are inadmissible for A(t) — fail-closed, never back-filled.
5. **Bootstrap implementation** — stationary block bootstrap on the
   daily IC series, mean block 21 trading days, 2,000 resamples,
   percentile CIs, with the RNG seed and the resampling algorithm
   committed as code in the harness.
6. **Controls** — positive (planted condition-dependent signal) and null
   (shuffle) synthetic controls with hard exit codes, committed and run
   under the frozen rules BEFORE the first real read.
7. **Fail-closed verdict machinery** — the harness refuses to emit
   Stage-C gate arithmetic before every §2b/§3 guard holds, and the
   verifier enforces the model#213 countersign rule on any non-null
   verdict.

Any deviation the harness PR needs makes THAT PR the visible, reviewed
amendment surface — never an execution-time interpretation.
