# Progress: G4 re-registration amendment v4

STATUS: revised RFC; v3 superseded before activation.

WHAT: replaces v3's mutable latest-commit schedule rule and under-specified
daily difference series with a canonical next-open observation, immutable
information/fill evidence, explicit failure handling, and a deployment-quality
economic threshold. It also assigns the shared API and daily execution work to
pipeline/common/orchestrator rather than to model-local helpers.

WHY/DIR: an ensemble result is not valid merely because it has a daily return
column. Without immutable PIT proof, executable fills/cash/cost accounting,
and an economic deployment criterion, it cannot justify advancing beyond L1.

EVIDENCE: model#58/#59 establish insufficient current evidence; model#60
exposes the close-anchor mismatch. Those findings motivate this new protocol
but do not validate an ensemble edge.

NEXT: independent review; implement the public schedule contract and run-bundle
path first, then backfill/parity evidence, then a blinded pilot. No capital or
L2 advancement is permitted by this RFC.
